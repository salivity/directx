DirectX 12 Feature Level 12_2 Requirements Explained

DirectX 12 Feature Level 12_2 represents a significant hardware baseline established by Microsoft, aligning closely with the DirectX 12 Ultimate branding to guarantee support for next-generation rendering technologies. Instead of treating advanced graphical techniques as optional extensions, Feature Level 12_2 codifies DirectX Raytracing (DXR) Tier 1.1, Mesh Shaders, and Variable Rate Shading (VRS) Tier 2 into a single, non-negotiable specification. For a GPU to be certified for Feature Level 12_2, hardware manufacturers must implement full native support across their architecture and driver stack, eliminating fragmentation and enabling game developers to build titles around these advanced capabilities without requiring legacy fallbacks.

The Mechanism of Direct3D Feature Levels

In Direct3D, a feature level defines a strict contract between the operating system, the graphics driver, and the physical GPU. When an application queries a device for Feature Level 12_2 via the API, the Direct3D runtime verifies that every mandatory capability bit (cap) within that tier is present.

Unlike API versioning, which allows optional features that developers must check individually via CheckFeatureSupport, feature levels act as all-or-nothing thresholds. If a GPU fails to support even one mandated sub-feature—such as inline raytracing or primitive-level shading rates—the driver cannot expose Feature Level 12_2.

Mandated Support for DXR Tier 1.1

DirectX Raytracing (DXR) Tier 1.1 builds upon the foundational raytracing capabilities introduced in Tier 1.0, shifting execution control from rigid fixed pipelines to more flexible shader stages. Feature Level 12_2 mandates DXR Tier 1.1 by requiring the following hardware capabilities:

  • Inline Raytracing: Hardware must allow any shader stage (compute, pixel, vertex, etc.) to traverse acceleration structures and query ray-object intersections directly via intrinsic functions, bypassing the overhead of full ray-generation shader dispatches.
  • Indirect Ray Dispatching: The GPU must support DispatchRays via indirect execution, allowing compute shaders to calculate and feed raytracing workloads directly to the hardware without CPU synchronization.
  • Runtime Pipeline State Updates: The architecture must allow dynamic additions to existing Raytracing Pipeline State Objects (RTPSOs) to optimize runtime compilation overhead.

Under FL 12_2, driver emulation of these features is prohibited. The physical graphics core must include dedicated acceleration hardware to traverse bounding volume hierarchies (BVHs) and process triangle intersection testing efficiently.

Mandated Support for Mesh Shaders

Feature Level 12_2 deprecates the legacy fixed-function geometry pipeline—which relied on Input Assembler, Vertex, Hull, Domain, and Geometry shaders—in favor of the more parallelized Mesh Shader pipeline. To achieve compliance, a GPU must implement:

  • Task Shaders (Amplification Stage): A programmable stage that operates similarly to a compute shader, capable of dynamically determining work volume and spawning a variable number of Mesh Shader threadgroups.
  • Mesh Shaders: A programmable stage that processes localized geometry clusters called "meshlets." The hardware must support direct output of indexed vertices and primitive topologies directly to the rasterizer.

FL 12_2 requires hardware to expose Mesh Shader Tier 1. The GPU microarchitecture must manage shared memory allocations and threadgroup distribution natively, enabling high-performance geometry culling, dynamic Level of Detail (LOD) transitions, and dense procedural generation before rasterization occurs.

Mandated Support for Variable Rate Shading (VRS) Tier 2

Variable Rate Shading allows a rendering engine to decouple the frequency of pixel shading from the resolution of the render target, allocating compute power to areas with high visual detail while reducing shading rates in blurred or shadowed regions. Feature Level 12_2 mandates VRS Tier 2, the most flexible and granular implementation of the technology.

Compliance requires hardware support for three distinct methods of specifying shading rates:

  1. Per-Draw (Tier 1): Setting a global shading rate for an entire draw call.
  2. Per-Primitive (Tier 2): Allowing the geometry or mesh shader to dictate shading rates on an individual primitive level.
  3. Screen-Space Shading Rate Image (Tier 2): Utilizing a low-resolution surface (shading rate image) to determine shading density across specific screen-space tiles.

Furthermore, Tier 2 requires the hardware to implement Combiners. When multiple shading rates are applied simultaneously—such as a per-primitive rate evaluated alongside a screen-space rate image—the GPU’s rasterizer must mathematically combine them using min, max, override, or sum operations to resolve the final sampling frequency.

Industry Impact

By mandating DXR 1.1, Mesh Shaders, and VRS Tier 2, Feature Level 12_2 establishes a definitive floor for modern PC and console architectures (including AMD RDNA 2 and newer, NVIDIA Turing and newer, and Intel Arc). This unification allows developers to optimize deeply for compute-driven geometry, selective shading, and hardware-accelerated ray tracing, knowing the target hardware will execute these commands natively and predictably.
