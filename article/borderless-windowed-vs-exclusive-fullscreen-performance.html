Borderless Windowed vs Exclusive Fullscreen Performance

For years, PC gamers favored exclusive fullscreen mode over borderless windowed mode to eliminate input lag and maximize frame rates. However, recent architectural improvements in Windows and the DirectX display pipeline—specifically the evolution of the DirectX Flip presentation model—have closed this performance gap entirely. This article explains the technical differences between borderless windowed and exclusive fullscreen modes, the historical limitations of windowed rendering, and how modern Flip presentation enables borderless windowed gaming to match exclusive fullscreen speed, latency, and feature support.

Understanding Display Modes: Fullscreen vs. Borderless Windowed

Exclusive Fullscreen (FSE) grants a game direct, uncontested control over the graphics pipeline and display hardware. By bypassing the Windows Desktop Window Manager (DWM), the game writes directly to the front buffer shown on the monitor. This method historically offered the lowest input latency, direct support for Variable Refresh Rate (VRR) technologies like G-Sync and FreeSync, and peak frame pacing. The drawback is poor multitasking: switching out of the game via Alt-Tab forces the display adapter to renegotiate video modes, causing monitor flickering, slow switching, and potential crashes.

Borderless Windowed mode runs the game inside a standard window stripped of title bars and borders, stretched across the entire resolution of the desktop. It allows instantaneous Alt-Tabbing and seamless cursor movement between multiple monitors. Historically, this convenience came with severe performance penalties because the game had to route its frames through the DWM alongside all other desktop elements.

The Problem with Legacy Windowed Rendering: The Blt Model

In legacy versions of DirectX (DirectX 9 through early DirectX 11), windowed applications used the "Blt" (Bit Block Transfer) presentation model.

Under the Blt model:

  1. The game renders a frame into an off-screen back buffer.
  2. The back buffer contents are copied into a DWM-managed surface.
  3. The DWM composites this surface with the rest of the desktop, enforcing its own vertical synchronization (V-Sync).
  4. The final composite image is sent to the display.

This multi-step copy-and-composite process introduced at least one to two frames of input latency, frequently locked frame rates to the desktop refresh rate, introduced micro-stuttering, and prevented tear-free variable refresh rate displays from synchronizing directly to the game engine.

The DirectX Flip Model: Eliminating the Overhead

To resolve the inefficiencies of the Blt model, Microsoft introduced the DXGI Flip model (specifically DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL and DXGI_SWAP_EFFECT_FLIP_DISCARD). Instead of copying image memory across buffers, the Flip model passes memory surface pointers between the application and the compositor, drastically reducing memory bandwidth overhead and processing time.

The real breakthrough for borderless windowed gaming comes from two key sub-features of the Flip model:

  • Direct Flip: When a borderless window covers the entire screen without any overlapping transparent windows, the DWM avoids compositing the desktop entirely. It binds the application's swap chain directly to the display pipeline.
  • Independent Flip (iFlip): Independent Flip goes a step further by removing the DWM completely from the presentation loop once full-screen coverage is established. The graphics hardware reads directly from the application's back buffers, identically to how Exclusive Fullscreen functions.

Because Independent Flip provides direct hardware scanout, it completely bypasses the DWM composition stage, dropping input latency to the exact level of Exclusive Fullscreen while maintaining the ability to resume desktop compositing instantly if an overlay appears.

Multi-Plane Overlays (MPO) and Variable Refresh Rates

Modern GPUs paired with display controllers that support Multi-Plane Overlays (MPO) further reinforce this parity. MPO allows the graphics card to scan out multiple separate surfaces simultaneously at the hardware level. A game running in borderless windowed mode can be scanned out on one hardware plane while system notifications, chat overlays, or volume sliders are processed on an independent hardware plane.

Because the game's surface remains independent, the GPU maintains full hardware synchronization with the display. Consequently, Variable Refresh Rate (G-Sync and FreeSync) and Custom Frame Rates function seamlessly without tearing, stutter, or added latency in borderless windowed mode.

Modern Windows Optimizations

With modern APIs like DirectX 12 and Vulkan, the Flip model is enforced by default, rendering Exclusive Fullscreen practically obsolete for newer titles.

For older games built on DirectX 10 and DirectX 11 that natively used the legacy Blt model, Windows 11 includes an engine-level feature called "Optimizations for Windowed Games." When enabled, the operating system intercepts legacy presentation calls and upgrades them automatically to the modern Flip model. This allows legacy titles to benefit from Independent Flip, low input latency, Auto HDR, and full VRR support while remaining in borderless windowed mode.
