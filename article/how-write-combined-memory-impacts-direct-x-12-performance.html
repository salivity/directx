How Write-Combined Memory Impacts DirectX 12 Performance

In DirectX 12, write-combined (WC) memory configuration dramatically accelerates CPU-to-GPU data transfers by grouping individual memory writes into single, burst-rate bus transactions. Primarily backing D3D12_HEAP_TYPE_UPLOAD heaps, WC memory bypasses the standard L1, L2, and L3 CPU cache hierarchies to optimize high-throughput linear writes across the PCI Express (PCIe) bus. While this architecture significantly enhances CPU writing speed for per-frame dynamic resources like constant buffers and vertex data, it requires strict adherence to sequential write patterns and completely penalizes CPU read operations.

The Mechanics of Write-Combining

Standard system memory relies on cached write-back semantics. When a CPU core writes to write-back memory, it first fetches the target cache line into its local L1/L2 cache—a process called Read-For-Ownership (RFO)—modifies the data, and eventually flushes it back to RAM. This process introduces latency and pollutes the CPU cache with transient graphics data that the processor will not read again.

Write-combined memory circumvents this overhead by treating the target memory region as weakly ordered and un-cached. Instead of writing directly to the standard cache hierarchy or issuing immediate, isolated memory writes:

  1. Internal Buffering: The CPU allocates internal hardware store buffers (often called Write-Combine Buffers or Fill Buffers).
  2. Batching Writes: Consecutive writes to adjacent memory addresses accumulate inside these 64-byte buffers (matching the CPU cache line size).
  3. Burst Flushing: Once a buffer is full, or when a serialization instruction executes, the entire 64-byte block transmits across the PCIe bus in a single burst transaction.

By eliminating the RFO phase and minimizing bus transactions, write-combining allows the CPU to saturate the write bandwidth of system memory and PCIe lanes.

Performance Gains for CPU Write Operations

In DirectX 12 rendering pipelines, the primary workload for write-combined memory involves frequently updated resources, such as uniform buffer objects, transform matrices, and dynamic procedural geometry mapped via ID3D12Resource::Map.

  • Elimination of Cache Eviction: Bypassing CPU caches preserves precious L2 and L3 cache space for game logic, physics, and AI threads rather than filling it with short-lived GPU data.
  • Maximum Write Bandwidth: Sequential streaming writes using SIMD intrinsics (such as SSE _mm_stream_si128 or AVX equivalents) can write directly into WC buffers without pipeline stalls, approaching hardware-limit throughput.
  • Low Latency for Small Updates: Batching multiple 4-byte or 8-byte updates into full 64-byte frames reduces memory interface contention.

Pitfalls and Performance Penalties

While write-combined memory offers peak throughput for unidirectional streaming, architectural trade-offs severely punish unoptimized access patterns:

  • Catastrophic Read Penalty: Write-combined memory is strictly write-optimized. Reading from a mapped WC resource forces the CPU to bypass the cache and fetch data directly from uncached system RAM or across the PCIe link, causing extreme pipeline stalls. CPU reads can be orders of magnitude slower than reading from regular cached memory.
  • Non-Sequential Write Degradation: If the CPU writes data non-sequentially, with large strides, or partially updates cache lines without filling the 64-byte buffer, the hardware prematurely flushes the write-combining buffer. This fragments the data stream into small, high-overhead bus transactions, collapsing write bandwidth.
  • Store Buffer Exhaustion: Modern CPUs possess a limited number of write-combining buffers (typically between 8 and 12). Concurrently writing to multiple disconnected upload resources causes buffer thrashing, triggering premature flushes.

Practical Guidelines for DirectX 12 Developers

To maximize CPU writing performance in DirectX 12 upload heaps:

  1. Write Sequentially: Structure data structures so that the CPU writes in linear, contiguous blocks from start to finish.
  2. Never Read Upload Memory: Never read from a pointer returned by Map on an upload heap. If an algorithm requires reading back data, calculate it in standard CPU heap memory first, then write the final result to the upload heap.
  3. Use SIMD/Optimized Memcpy: Utilize memory-copy routines that take advantage of non-temporal stores or auto-vectorization to fill entire 64-byte cache lines consistently.
  4. Finish Resources Individually: Complete writes to one dynamic resource before moving to another to avoid exceeding the CPU's hardware store buffer capacity.
