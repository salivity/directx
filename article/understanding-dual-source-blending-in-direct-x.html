Understanding Dual-Source Blending in DirectX

Dual-source blending is a graphics hardware feature that allows a pixel shader to output two distinct colors to a single render target simultaneously, using the second output as a dynamic blend factor. In DirectX, this capability provides fine-grained control over color combination operations without requiring multiple passes or framebuffer readbacks. This article explores the mechanics of dual-source blending within the DirectX API and highlights specialized rendering techniques that depend on it, including subpixel font rendering and order-independent transparency.

What Is Dual-Source Blending?

In standard rasterization pipelines, a pixel shader typically writes one color value (SV_Target0) to a render target. When Multiple Render Targets (MRT) are used, the shader writes to separate textures (e.g., SV_Target0 to Render Target 0, SV_Target1 to Render Target 1).

Dual-source blending modifies this behavior. Instead of directing the second output to a separate buffer, the hardware routes both outputs to the blend stage of a single render target (typically Render Target 0). In DirectX HLSL, the shader outputs two vectors marked with SV_Target0 and SV_Target1. In the blend state description, SV_Target0 acts as the primary source (D3D11_BLEND_SRC_COLOR / D3D12_BLEND_SRC_COLOR), while SV_Target1 serves as an additional operand (D3D11_BLEND_SRC1_COLOR, D3D11_BLEND_SRC1_ALPHA, or their inverse counterparts).

This allows the blend stage to execute mathematical operations where every color channel of the primary output can be multiplied by an arbitrary, per-pixel mask generated dynamically by the same shader.

Specialized Techniques Utilizing Dual-Source Blending

1. Subpixel Font Rendering

The most common use case for dual-source blending is subpixel text rendering (similar to Microsoft ClearType). LCD screens arrange subpixels physically as independent Red, Green, and Blue stripes. Anti-aliasing text at the subpixel level requires treating each color channel independently:

  • Without Dual-Source Blending: Standard alpha blending uses a single scalar alpha for all three color channels, requiring multipass rendering or costly texture readbacks to apply an RGB mask to the destination.
  • With Dual-Source Blending: The pixel shader outputs the font color in SV_Target0 and the per-channel coverage mask in SV_Target1. The blend equation uses D3D12_BLEND_SRC1_COLOR as the source blend factor and D3D12_BLEND_INV_SRC1_COLOR as the destination blend factor, applying full subpixel anti-aliasing in a single pass.

2. Order-Independent Transparency (OIT)

Certain Order-Independent Transparency algorithms, particularly variations of Weighted, Blended OIT, evaluate complex absorption and transmission functions concurrently:

  • In these algorithms, transparent surfaces contribute to both an accumulated color buffer and a revealage/coverage buffer.
  • Dual-source blending allows the shader to write a weighted color value while simultaneously utilizing the secondary source to compute complex transmission decay against the destination buffer, reducing memory bandwidth compared to using MRT.

3. Advanced Decals and Layered Materials

Deferred decal rendering often requires blending multiple surface properties (such as albedo, roughness, and metalness) with custom non-linear weighting equations. Dual-source blending enables complex decals to apply distinct blending operations to color and masking terms within a single draw call, ensuring that transparent borders and edge wear integrate cleanly into existing G-buffer layouts.

DirectX Implementation Considerations

To utilize dual-source blending in DirectX 11 or DirectX 12:

  1. Blend State Configuration: Configure the D3D11_RENDER_TARGET_BLEND_DESC or D3D12_RENDER_TARGET_BLEND_DESC structure so that SrcBlend, DestBlend, SrcBlendAlpha, or DestBlendAlpha use the _SRC1_ enumerations (e.g., D3D12_BLEND_SRC1_COLOR or D3D12_BLEND_INV_SRC1_COLOR).

  2. HLSL Output Signature: The pixel shader must return a structure containing two render target semantics:

    struct PixelOutput
{
    float4 Color : SV_Target0;
    float4 Factor : SV_Target1;
};

  3. Hardware Constraints: When dual-source blending is active, hardware limits binding to only one active render target. MRT cannot be combined with dual-source blending on modern graphics pipelines.
