Shader Execution Reordering in DirectX Ray Tracing

Shader Execution Reordering (SER) optimizes ray tracing performance in DirectX by dynamically reorganizing incoherent GPU workloads into coherent execution threads on the fly. In real-time ray tracing, rays bounce off surfaces in unpredictable directions, causing neighboring GPU threads to execute different shaders or access distant memory locations. SER acts as a real-time sorting mechanism that groups threads performing similar work into the same execution warps, dramatically reducing execution and memory divergence and maximizing GPU hardware utilization.

The Divergence Bottleneck in Ray Tracing

Modern GPUs rely on Single Instruction, Multiple Threads (SIMT) architectures, where groups of threads (termed warps or wavefronts) execute the same instruction in lockstep across multiple ALU lanes. This model works exceptionally well for rasterization, where neighboring pixels share the same materials and screen-space alignment.

Ray tracing breaks this model through two distinct types of divergence:

  1. Shader Execution Divergence: When secondary rays (such as reflections, refractions, or diffuse global illumination) hit different surfaces, neighboring threads must execute entirely different Closest Hit Shaders (CHSs). If 32 threads in a warp hit 32 different materials, the GPU must serialize the execution of each unique shader while the remaining threads sit idle, causing severe underutilization of execution units.
  2. Data and Memory Divergence: Even when rays execute the same shader code, rays traveling in divergent directions fetch geometry, textures, and acceleration structure nodes from disjointed memory regions. This thrashes L1 and L2 caches, causing high memory latency and bandwidth saturation.

How Shader Execution Reordering Solves Divergence

Shader Execution Reordering transforms divergent, chaotic workloads into uniform, aligned threads before those threads execute compute-heavy shader logic.

In a typical DirectX Raytracing (DXR) pipeline without SER, the system processes a ray from generation to traversal, executes the closest hit shader, and returns control to the caller. If execution diverges, performance degrades immediately.

With SER enabled, the ray traversal and shader execution phases are decoupled:

  1. Hit Evaluation: Rays traverse the Bounding Volume Hierarchy (BVH) and identify hit points. Instead of immediately invoking the corresponding Closest Hit Shader, the runtime generates a lightweight record (often represented as a "Hit Object").
  2. Dynamic Sorting and Clustering: The GPU hardware and driver analyze the pending Hit Objects across concurrent waves. Threads with matching execution requirements—such as those invoking the same shader or accessing contiguous spatial data—are gathered and sorted.
  3. Coherent Dispatch: The GPU repacks these sorted threads into new, coherent warps. When the actual hit shaders execute, all threads within a given warp evaluate identical code paths and access localized memory.

Implementation in DirectX

Within DirectX Raytracing, SER is leveraged through modern API extensions and HLSL constructs, primarily utilizing Ray Queries or dynamic Hit Objects rather than traditional monolithic TraceRay calls.

Developers utilize APIs (such as those exposed by NVIDIA’s NVAPI or modern cross-vendor DXR enhancements) to split the tracing process into two explicit stages:

  • Tracing to Hit Object: The shader issues a trace command that yields a HitObject rather than immediately executing an inline or callable shader.
  • Reorder Execution: The shader explicitly calls an execution-reordering intrinsic on the HitObject. The GPU pauses the wave, collects Hit Objects across the streaming multiprocessors, groups like-with-like, and resumes execution with newly organized warps.

Impact on Hardware Utilization

By resolving divergence at runtime, SER provides measurable hardware-level advantages:

  • Elimination of Inactive SIMD Lanes: Warps no longer waste compute cycles masking out inactive threads during material evaluation, dramatically raising floating-point (FP32) utilization.
  • Improved Cache Hit Rates: Coherent memory access patterns allow the L1 and L2 caches to retain and reuse texture data, material properties, and geometry buffers effectively.
  • Scalable Path Tracing: Complex lighting models like full path tracing, which rely on multi-bounce diffuse and glossy calculations, shift from being bottlenecked by thread divergence to scaling predictably with raw compute power.
